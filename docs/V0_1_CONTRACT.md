# siloBrief v0.1 기능명세서

- 문서 상태: `FROZEN FOR IMPLEMENTATION`
- 계약 버전: `1`
- 확정일: 2026-08-03 (Asia/Seoul)
- 기준 문서: `documents/CLOSED_ENV_BRIEF_FINAL_HANDOFF.md`

이 문서는 `siloBrief` v0.1의 구현 범위와 외부 동작을 고정한다. 구현 중 새로운 기능이 필요해 보이더라도 이 문서를 먼저 명시적으로 개정하지 않는 한 추가하지 않는다.

외부 검색자 실험은 제품 기능이 아니며 v0.1 구현의 선행 조건에서 제외한다. 이는 사람 대상 효과나 시장 수요가 검증됐다는 뜻이 아니다. v0.1은 대회 제출과 기술 가능성 확인을 위한 제한된 시제품이다.

## 1. 제품 정의

> 인터넷이 분리된 개발환경에서 작은 Python 프로젝트를 로컬로 분석하고, 사용자가 선언한 공개 경계와 최종 승인을 적용해 검색 PC용 Markdown 조사 브리프 한 파일을 만드는 CLI.

- 첫 사용자: 프로젝트 구조를 알고 있는 Python 유지보수 개발자
- 해결할 상황: 소스 전체를 옮길 수 없는 검색 환경에 조사에 필요한 맥락을 다시 설명해야 함
- 관찰 가능한 결과: 허용된 구조 정보와 사람 메모만 포함한 검토 가능한 Markdown 한 파일 생성
- 가장 큰 미검증 가정: 도구의 후보 확인과 공개 검토가 수동 브리프 작성보다 덜 번거로운가

## 2. 고정 범위

| 항목 | v0.1 계약 |

| 표시 이름 | `siloBrief` |

## 3. 사용자 흐름

v0.1의 유일한 정상 흐름은 다음과 같다.

```text
setup
→ ignore 0회 이상
→ init
→ log 0회 이상
→ chat
→ 후보 선택·공개 필드 확인
→ 전체 Markdown 미리보기
→ 사용자의 명시적 승인
→ 새 Markdown 파일 생성
```

`chat`은 AI 대화 기능이 아니다. 요청 한 건을 조사 브리프 한 건으로 만드는 대화형 검토 명령이다.

## 4. 공개 CLI

```text
sb setup [PATH]
sb ignore PATH --as TEXT [--alias NAME]
sb init
sb log PATH --comment TEXT
sb chat "PROMPT" --out FILE
sb --version
```

### 4.1 공통 동작

- `setup`의 `PATH`를 제외한 명령은 프로젝트 루트 또는 그 하위에서 실행한다.
- 상태 디렉터리를 찾지 못하면 입력·설정 오류로 종료한다.
- 사용자에게 표시하거나 직렬화하는 프로젝트 경로는 `/` 구분자의 프로젝트 상대 경로만 사용한다.
- 성공 메시지는 수행한 동작과 생성·갱신한 상태 파일을 표시한다.
- 오류는 명령, 단계, 관련 경로와 원인을 표시한다.
- 예상 가능한 실패를 traceback만으로 전달하지 않는다.
- 파일을 덮어쓰거나 승인 단계를 우회하는 옵션은 없다.

### 4.2 `setup [PATH]`

프로젝트 루트와 로컬 상태를 초기화한다.

- `PATH` 생략 시 현재 디렉터리를 사용한다.
- 존재하는 디렉터리만 프로젝트 루트로 받을 수 있다.
- 프로젝트 루트 자체가 symbolic link이면 거부한다.
- `.silobrief/`와 버전 `1`의 설정을 만든다.
- 기본 제외 규칙은 `.git/`, `.silobrief/`, `__pycache__/`, `.venv/`, `venv/`, `build/`, `dist/`이다.
- `.silobrief/exports/`를 생성한다.
- 소스 파일과 기존 프로젝트 설정은 수정하지 않는다.
- 같은 루트에 유효한 v0.1 상태가 이미 있으면 아무것도 바꾸지 않고 성공한다.
- 상태가 일부만 있거나 schema가 호환되지 않으면 자동 복구하거나 덮어쓰지 않고 종료 코드 `2`로 실패한다.

### 4.3 `ignore PATH --as TEXT [--alias NAME]`

프로젝트 안의 파일 또는 디렉터리를 분석 대상에서 제외하고 공개용 경계 설명을 등록한다.

- `PATH`는 프로젝트 안에 존재하는 파일 또는 디렉터리여야 한다.
- 절대 경로, `..`를 포함한 경로, 프로젝트 밖으로 해석되는 경로, symbolic link 또는 symbolic link를 통과하는 경로는 거부한다.
- `TEXT`는 비어 있을 수 없으며 공개 가능한 설명이라고 간주한다.
- `NAME`은 영문 소문자, 숫자와 `-`만 사용한 1~40자 alias다.
- `NAME`을 생략하면 실제 경로명에서 유도하지 않은 `boundary-N`을 등록 순서대로 부여한다.
- 실제 제외 경로는 로컬 설정에만 저장한다. 브리프와 disclosure manifest에는 기록하지 않는다.
- 같은 경로와 같은 값의 재등록은 변경 없이 성공한다. 같은 경로에 다른 값이 이미 있으면 종료 코드 `2`로 실패한다.
- 제외 규칙 변경 후에는 기존 인덱스를 오래된 상태로 표시하며 다음 `chat` 전에 `init`을 다시 실행해야 한다.

### 4.4 `init`

현재 공개 경계를 적용해 버전 `1`의 결정적 로컬 구조 인덱스를 만든다.

- 제외 규칙을 디렉터리 순회와 파일 열기보다 먼저 적용한다.
- symbolic link는 따라가지 않는다. 발견한 상대 경로와 건너뛴 이유를 경고한다.
- 허용된 `.py` 파일만 `ast`와 `tokenize`로 읽는다.
- 모듈, 클래스, 함수, import, 호출·참조 관계, docstring·일반 주석의 검색 토큰을 추출한다.
- 문자열 리터럴은 검색 인덱스에 넣지 않는다. docstring은 문자열 리터럴과 구분해 검색용으로만 처리한다.
- 제외 영역과 일치하는 import·참조는 JSON에 쓰기 전에 `boundary-placeholder`로 바꾼다.
- placeholder에는 alias와 사용자 설명만 저장하고 실제 제외 경로·모듈·심볼 이름은 저장하지 않는다.
- 허용 파일의 구문 분석에 실패하면 파일과 원인을 표시하고 종료 코드 `3`으로 전체 실행을 실패시킨다.
- 실패 시 기존의 유효한 인덱스를 부분 결과로 교체하지 않는다.
- 모든 ID는 정규화된 상대 경로와 심볼 종류·정규명으로 안정적으로 만든다.
- 객체 key와 배열 순서를 고정하며 현재 시각, 절대 경로와 OS 전용 값을 인덱스에 넣지 않는다.
- 같은 소스와 설정은 반복 실행 및 지원 OS에서 의미상 같은 JSON을 만든다.
- 인덱싱 전후 허용 소스 파일의 SHA-256을 비교한다. 달라졌으면 인덱스를 확정하지 않고 종료 코드 `4`로 실패한다.

### 4.5 `log PATH --comment TEXT`

코드 구조만으로 알 수 없는 공개 가능한 유지보수 메모를 기록한다.

- `PATH`는 프로젝트 안의 허용된 파일 또는 디렉터리여야 한다.
- 제외된 경계, 프로젝트 밖 경로와 symbolic link에는 메모를 연결할 수 없다.
- `TEXT`는 비어 있을 수 없다.
- 저장 전에 이 문장이 최종 브리프에 포함될 수 있다는 경고를 표시한다.
- 메모는 작성 순서를 보존하되 결정적인 ID를 부여한다.
- 브리프에서는 반드시 `사용자 작성 메모`로 출처를 표시한다.
- 메모 추가·변경은 코드 구조 인덱스를 무효화하지 않는다.

### 4.6 `chat "PROMPT" --out FILE`

요청 하나에 대해 후보를 제안하고 사람이 확인한 Markdown 조사 브리프를 생성한다.

사전 조건:

- `PROMPT`는 비어 있을 수 없다.
- 현재 설정과 일치하는 유효한 인덱스가 있어야 한다.
- 표준 입력과 출력이 TTY여야 한다.
- `FILE`은 `.md` 확장자의 새 파일이어야 하며 부모 디렉터리가 존재해야 한다.
- `FILE`이 프로젝트 안이면 `.silobrief/exports/` 아래만 허용한다.
- 기존 파일 또는 symbolic link는 덮어쓰지 않는다.

동작 순서:

1. 요청을 Unicode casefold하고 식별자·공백·구두점 단위로 정규화한다.
2. 모듈 경로, 심볼, 공개 import, docstring·주석 검색 토큰과 사용자 메모의 어휘 겹침을 계산한다.
3. 어휘 겹침, 연결도와 사용자 메모 일치 여부로 설명 가능한 점수를 만들고 상위 후보 10개까지 표시한다.
4. 각 후보에 상대 경로, 심볼 종류·이름과 점수 근거를 표시한다. 소스 본문, 주석과 docstring 원문은 표시하지 않는다.
5. 사용자가 후보 번호를 선택한다. 자동으로 선택하거나 정답이라고 표시하지 않는다.
6. 사용자는 인덱스에 있는 정확한 상대 경로·심볼 ID를 추가하거나 선택 항목을 제외할 수 있다.
7. 시작 후보가 하나도 없으면 계속하지 않는다.
8. 선택 후보에서 허용된 간선을 한 단계만 확장하고, 추가될 필드를 다시 보여준다.
9. 상대 경로, 심볼, 공개 라이브러리, 사용자 메모와 경계 placeholder를 각각 포함·제외하도록 확인받는다.
10. 완성된 Markdown 전체와 disclosure manifest를 터미널에 미리 표시한다.
11. 사용자가 정확히 `WRITE`를 입력한 경우에만 새 파일을 쓴다.

사용자가 취소하거나 `WRITE`를 입력하지 않으면 파일을 만들지 않고 종료 코드 `4`로 종료한다. `--yes`, 기본 승인, non-TTY 승인과 자동 전송은 제공하지 않는다.

### 4.7 `--version`

- 설치된 제품 버전을 `siloBrief X.Y.Z` 형식으로 출력한다.
- 프로젝트 설정이나 네트워크가 없어도 종료 코드 `0`으로 동작한다.

## 5. 로컬 상태 계약

```text
.silobrief/
├─ config.json
├─ index.json
├─ notes.json
└─ exports/
```

- `config.json`: schema version, 기본 제외와 사용자 경계의 실제 로컬 경로·alias·설명
- `index.json`: index version, 설정 digest, 허용 구조 그래프, 검색 토큰, source digest
- `notes.json`: notes version과 사용자 작성 메모
- `exports/`: 승인된 Markdown 브리프

세 JSON은 UTF-8, LF, 정렬된 key와 고정된 배열 순서를 사용한다. 비밀번호, 토큰, Git remote와 환경 변수 값은 저장하지 않는다. 상태 파일은 외부 전달용 산출물이 아니며 브리프에 자동 포함하지 않는다.

## 6. 검색과 선택 계약

- 검색은 lexical 후보 제안이며 의미 검색이나 정확도 보장을 표방하지 않는다.
- snake_case, camelCase와 PascalCase를 단어로 나눈다.
- 한글 요청과 영어 식별자의 의미 번역을 추정하지 않는다.
- 동점은 정규화 상대 경로, 심볼 종류, 심볼 이름 순으로 정렬한다.
- 점수 구성 요소와 후보가 나타난 이유를 사용자가 확인할 수 있어야 한다.
- 후보가 부정확할 때 사용자가 정확한 경로나 심볼을 직접 선택할 수 있어야 한다.
- 선택하지 않은 후보는 브리프 renderer에 전달하지 않는다.

## 7. Markdown 브리프 계약

Markdown은 다음 섹션을 정확히 이 순서로 포함한다.

1. `경고와 용도`
2. `원래 작업 요청`
3. `선택한 프로젝트 맥락`
4. `사용자 작성 메모`
5. `숨긴 경계`
6. `조사 질문`
7. `추천 검색어`
8. `외부 AI에 복사할 프롬프트`
9. `Disclosure manifest`
10. `수동 확인 체크리스트`

`외부 AI에 복사할 프롬프트`는 사용자가 검색 PC에서 선택적으로 복사할 템플릿일 뿐, 도구가 AI를 호출하거나 전송한다는 뜻이 아니다.

renderer가 받을 수 있는 프로젝트 유래 필드는 다음으로 제한한다.

- 사용자가 입력한 원래 요청
- 사용자가 이번 실행에서 승인한 상대 경로
- 사용자가 승인한 심볼 종류와 이름
- 사용자가 승인한 공개 라이브러리 이름
- 사용자가 승인한 사용자 작성 메모
- 경계 alias와 사용자가 작성한 공개 설명

다음은 브리프에 직렬화하지 않는다.

- 함수·클래스·모듈의 소스 본문
- 주석과 docstring 원문
- 문자열 리터럴
- 환경 변수 이름과 값
- 절대 경로와 사용자 홈 경로
- Git remote와 commit 이력
- 제외 경로·모듈·파일·심볼의 실제 이름
- 제외 영역에서 읽거나 추론한 정보

조사 질문, 추천 검색어와 복사용 프롬프트는 허용 필드만 고정 템플릿으로 조합한다. 자연어 의미를 새로 추론하거나 내용을 보강하지 않는다.

Disclosure manifest는 renderer가 실제 사용한 필드 종류와 개수를 기록한다. 최소 key는 다음과 같다.

```yaml
disclosure:
  user_prompt: included
  relative_paths: 0
  symbol_names: 0
  public_dependencies: 0
  human_notes: 0
  boundary_aliases: 0
  source_bodies: 0
  comments: 0
  docstrings: 0
  string_literals: 0
  absolute_paths: 0
  git_remotes: 0
  ignored_real_names: 0
```

## 8. 공개 경계와 안전 계약

도구가 보장해야 하는 동작:

- 명시적으로 제외한 subtree는 열거나 파싱하지 않는다.
- 모든 제외 검사는 인덱싱보다 먼저 수행한다.
- 프로젝트 밖으로 향하는 `..`, 절대경로, Windows 구분자 우회와 symlink 탈출을 거부한다.
- 제외 영역으로 향하는 알려진 정적 import·reference의 실제 이름은 직렬화 전에 placeholder로 바꾼다.
- renderer는 7장의 whitelist 필드 외 값을 받을 수 없다.
- 네트워크 연결을 시작하지 않는다.
- 사용자의 승인이 있기 전과 승인 거부 후에는 Markdown 파일을 쓰지 않는다.
- `.silobrief/`를 제외한 기존 프로젝트 파일을 수정하지 않는다.

도구가 보장하지 않는 것:

- 사용자가 요청·메모·허용 이름에 직접 넣은 민감 정보의 탐지
- 허용 파일 안에서 민감한 식별자를 자동 판별하는 기능
- 동적 import와 런타임 생성 참조의 완전한 경계 탐지
- 운영체제나 다른 로컬 프로세스에 대한 sandbox
- 조직의 반출 승인, 보안 인증 또는 누출 방지 보장

README, CLI preview와 결과보고서에는 다음 한계를 같은 의미로 표시한다.

> 경로 단위 ignore는 허용된 파일 안에 있는 민감한 식별자를 보호하지 못한다. 이 산출물은 자동 보안 검사를 통과한 문서가 아니며 이동 전에 사람이 전체 내용을 확인해야 한다.

## 9. 종료 코드

| 코드 | 의미 |
|---:|---|
| `0` | 성공 |
| `1` | 예상하지 못한 내부 오류 |
| `2` | 입력, 경로 또는 설정 오류 |
| `3` | 인덱싱 또는 Python 파싱 오류 |
| `4` | 경계 검증 실패, 승인 거부 또는 보고서 생성 차단 |

내부 오류 `1`은 원인 확인을 위해 traceback을 stderr에 표시할 수 있다. 코드 `2`~`4`는 사용자가 고칠 수 있는 원인을 평문으로 표시한다.

## 10. 필수 수용 기준

### AC-01 전체 흐름

공개 fixture에서 `setup → ignore → init → log → chat`을 수행하고 승인 후 Markdown 한 파일을 생성한다.

### AC-02 결정성

같은 입력, 설정, 메모와 선택은 반복 실행 및 Windows·Ubuntu에서 의미상 같은 `index.json`과 Markdown을 만든다. 현재 시각, 절대 경로와 OS별 경로 구분자가 결과에 영향을 주지 않는다.

### AC-03 제외 subtree

제외 subtree의 파일 열기·파싱 시도를 계측했을 때 0회이며, 그 안의 canary가 인덱스·후보·브리프 어디에도 나타나지 않는다.

### AC-04 경계 placeholder

허용 파일이 제외 모듈을 정적으로 참조해도 실제 제외 이름이 직렬화된 인덱스와 브리프에 없고 승인된 alias와 설명만 나타난다.

### AC-05 renderer whitelist

허용 파일의 source body, 일반 주석, docstring과 문자열에 각각 넣은 canary가 브리프·추천 검색어·복사용 프롬프트에 나타나지 않는다. whitelist 밖 필드를 renderer에 전달하면 생성이 실패한다.

### AC-06 경로 방어

절대경로, `..`, 혼합 Windows 구분자, 프로젝트 밖 경로와 symlink 탈출을 각각 거부한다.

### AC-07 사람 승인

승인 거부, non-TTY와 기존 출력 파일에서 Markdown을 쓰지 않고 코드 `4`로 종료한다. `WRITE` 승인 전에는 임시 최종 파일도 남기지 않는다.

### AC-08 소스 불변

전체 흐름 전후에 `.silobrief/`를 제외한 기존 프로젝트 파일의 경로와 SHA-256이 동일하다.

### AC-09 오프라인

전체 테스트에서 네트워크 연결 시도가 0회이고 네트워크가 없는 Windows·Ubuntu에서도 정상 흐름이 동작한다.

### AC-10 파싱 실패

허용된 Python 파일에 구문 오류가 있으면 해당 파일과 원인을 표시하고 코드 `3`으로 종료하며 기존 인덱스를 교체하지 않는다.

### AC-11 설치 재현

wheel을 새 Python 3.10 이상 환경에 설치한 뒤 5분 안에 동일한 공개 fixture 데모를 재현할 수 있다.

## 11. 완료 정의

v0.1 기능 완료는 다음을 모두 만족한 상태다.

- 공개 CLI 여섯 진입점이 이 계약대로 동작한다.
- AC-01부터 AC-11까지 자동 또는 기록 가능한 acceptance test가 통과한다.
- 공개 fixture와 데모에 실제 조직·저장소·업무 정보가 없다.
- README의 기능, 한계, 명령과 종료 코드가 이 문서와 일치한다.
- Apache-2.0 라이선스와 설치 가능한 wheel이 있다.
- Windows와 Ubuntu에서 같은 1개 end-to-end 데모가 재현된다.

## 12. v0.1에서 하지 않는 것

1. LLM, embedding, 의미 검색, 멀티턴 대화
2. 웹·데스크톱 UI, 서버, daemon, 네트워크·USB 자동 전송
3. Python 이외 언어, 증분 인덱싱, 대규모 monorepo 최적화
4. secret scanner, 자동 비식별화, 보안 인증, 조직 승인 정책
5. 플러그인, 그래프 DB, 계정·권한·협업 기능

## 13. 허용·금지 표현

허용:

- “사용자가 선언한 경계를 인덱싱 전에 적용한다.”
- “fixture의 알려진 금지 문자열이 인덱스와 브리프에서 검출되지 않았다.”
- “네트워크 없이 로컬에서 동작하고 생성 전 전체 내용을 사람이 확인한다.”

금지:

- “민감 정보가 절대 유출되지 않는다.”
- “자동으로 안전하게 마스킹한다.”
- “군 또는 조직의 보안·반출 규정을 충족한다.”
- “시장 수요와 사용자 효과가 검증됐다.”

이 계약의 구현은 기술 시제품의 완성을 의미한다. 사람의 검색 효과, 반복 사용 수요와 실제 조직의 정책 적합성은 별도 근거 없이는 검증된 것으로 표현하지 않는다.
